為什麼換

搬過來不會痛

repository 路徑、Docker 連接埠、帳號模型都沿用 Nexus 的慣例。實際做過一次正式環境切換：同一台主機、同樣的連接埠，CI 設定一行都沒改。

它很小

單一 Go 執行檔，不需要 JVM、外掛或應用伺服器。幾秒內開始服務，在真實 CI 負載下記憶體用量維持在數百 MB。

上游壞掉時照樣出貨

已快取的內容在公開來源連不上時仍然供應，Maven Central 出狀況的那個下午不會讓你們的建置全部停擺。

沒有功能被留在付費版

因為沒有付費版。Apache 2.0，所有功能，不限元件數，不限請求數。

一行指令跑起來

$ docker compose -f deploy/docker-compose.yml up -d

然後開啟 http://localhost:8081/ui/。客戶端的設定方式和 Nexus 完全一樣：

mvnMavensettings.xml
<mirror>
  <id>holiaokho</id>
  <url>http://localhost:8081/repository/maven-public/</url>
  <mirrorOf>*</mirrorOf>
</mirror>
npmnpm.npmrc
npm config set registry http://localhost:8081/repository/npm-group/
dkrDockerdocker pull
docker pull localhost:8081/docker-hub/alpine:3.19

設定

一份能跑的設定就這麼短。每個設定都可以改用 HOLIAOKHO_* 環境變數給定，在容器裡通常會這樣做。

server:
  listen: ":8081"
database:
  url: "postgres://holiaokho:PASSWORD@localhost:5432/holiaokho?sslmode=disable"
storage:
  type: fs              # fs | s3
  path: ./data/blobs
auth:
  anonymous_enabled: true
  session_ttl: 30m
log:
  level: info

名字的由來

台語的「好料」（hó-liāu）是好東西、好材料——上等的食材、紮實的用料，家裡有好料，是客人來了值得端出來的那種。「庫」（khòo）是存放的地方。合起來就是：放好東西的地方。

你們建置時倚賴的套件、每次出版產出的成品，正是這樣的東西——值得好好收在一個可靠、隨手拿得到的地方。

Logo 是「广」字的屋頂，底下堆著貨，一座倉房；那道琥珀色的線，是留著的燈。
